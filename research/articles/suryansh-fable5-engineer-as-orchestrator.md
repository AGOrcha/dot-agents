## TL;DR

Software engineering keeps getting new abstraction layers (assembly → C → frameworks → cloud →
copilots), and the next layer is "intelligence itself." The bottleneck was never typing speed but
reasoning through complexity; reasoning scales and humans don't. Fable 5 is framed as a shift from
"prompt → response → done" to a long-horizon "research → plan → implement → test → refactor →
verify" workflow, with multi-file refactoring as the underrated killer feature. The endgame looks
like an engineering *organization* of specialized agents; the human's job becomes directing
intelligence, not writing lines. Value shifts from "can you write code?" to "can you direct
intelligence?"

## Body (faithful distillation)

- **Abstraction-layer framing.** Each era abstracts the last; the next abstraction is programmable
  intelligence. "I write every line" → "I direct systems that write, reason, and improve code for
  me." Claimed to be bigger than on-prem → cloud. [asserted]
- **Complexity wall.** Modern systems exceed any single engineer's head; the real work is reasoning
  through complexity, which is why staff engineers/architects are paid to understand systems. AI is
  powerful "because reasoning scales, humans don't." [asserted]
- **Different kind of system, not a better chatbot.** Real engineering is a *long-running reasoning
  problem*: research, read docs, understand the codebase, plan, write, test, debug, refactor,
  verify. Fable 5 is claimed to maintain context and coordinate multi-step work closer to this
  workflow than prior models. [asserted]
- **Long-horizon reasoning.** The hard questions ("why was this architecture chosen?", "what breaks
  if I change this API?", "which services depend on this module?", "is this tech debt?") need
  sustained context; historically models forgot objectives, lost context, looped. The engineer's
  value is decision quality, not finger speed.
- **Multi-file refactoring as killer feature.** Generating one file is easy; changing 50
  interconnected files across backend/frontend/APIs/schemas/tests/docs/CI/infra without breaking
  prod is real engineering. Claims Fable 5 "behaves like an engineer operating inside a codebase."
  [asserted]
- **Org-of-agents endgame.** Not one giant model — Planner / Research / Coding / Testing / Security
  / Deployment agents; the engineer is the orchestrator, "the manager of intelligence… the
  operating system for an AI workforce."
- **Prompting as the new programming skill.** Five example prompts (Architecture Review as a Staff
  Engineer; cross-file Refactor with migration checklist; Autonomous Debugging via hypotheses;
  production System Design; an "engineering copilot" that challenges assumptions).
- **What's next.** Small teams / solo founders run "engineering organizations"; value shifts from
  writing code to directing intelligence. "The age of managing AI engineers may be next."
