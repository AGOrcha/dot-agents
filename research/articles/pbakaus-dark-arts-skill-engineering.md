## Summary

Nine "dark arts" that take a skill from vibed prose to a battle-hardened harness extension.
The thesis: **a skill is a harness extension (a plugin), not a saved prompt** — "prompting
summons the median; the harness conjures the rest." Effective skills move work out of prose the
model *might* honor and into machinery that *forces* the outcome, so a non-deterministic model
behaves like deterministic software. Drawn from building Impeccable (a design harness shipped to
hundreds of thousands of users across Codex/Claude Code/Copilot).

## Body

### Most skills are a prompt and a prayer

Most skills are vibed prose: generated by the same model they target, tested twice, declared
working, enshrined in the skills directory. That's fine until you send it to others — then it has
to work **consistently, in every popular harness/agent, on projects unlike yours, with different
prompting styles, more than once or twice, on frontier and weaker models, on different OSes.**

### A skill is a harness extension

Reframe the skill as a **plugin** that extends Codex/Claude Code/Copilot in areas where they have
definite gaps — not a saved prompt to retrieve.

### Great skills make the model do something it really doesn't want to

If the model naturally wanted to do it, you wouldn't need the skill. (Codex+GPT doesn't want to
ask the user questions first; Claude+Opus/Fable wants italic serifs, eyebrow kickers, pulsating
green dots; all models want to over-write descriptive text.) **The median is the model's
gravity.** Every dark art below moves work from prose the model *might* honor into machinery that
*forces* the outcome.

### The nine dark arts

**#1 — Make them argue** (code review, security audits, plan/RFC critique, ranking).
Agents are biased toward their own work; a stronger "be unbiased!!" prompt fails. Use
**adversarial sub-agents**. Impeccable's `/critique` spawns two sub-agents that never see each
other's work — A = an LLM design director (hierarchy, slop, heuristics), B = a deterministic
detector + browser evidence — then the main agent **synthesizes (weave, never concatenate)**.
Handing the detector output up front skews both ways (noisy→false alarm; silent→rubber-stamp).
"Two blind opinions beat one confident guess." *Codex wrinkle:* sub-agents aren't portable — on
Codex a skill can't spawn one unless the user allowed parallel work / YOLO mode, so instruct "if
you can't spawn sub-agents, STOP and ask the user." (GPT 5.6 is reportedly more trigger-happy
with sub-agents.)

**#2 — Force divergence** (naming, branding, ideation, breaking boilerplate).
A ban (`don't use Inter`) just moves the model to the next-best pick — "purple-gradient AI slop
to serif beige AI slop." Bans move between regions of latent space; the escape is **sideways, not
a longer denylist.** Three stackable techniques (weak→strong): (a) *shave the safe picks* — make
it name its top 3, discard all 3; (b) *generate ~50, a blind sub-agent keeps the 5 most
distinct*; (c) *seed from outside the model* — `palette.mjs --from 8f2a` starts in a region the
model never picks on its own.

**#3 — Route like a frontier model** (big multi-tool skills, context on demand, per-audience).
Frontier models (Fable, GPT 5.6) are sensitive to over-corrective/conflicting prose — resist the
mile-long SKILL.md. Use **skill-internal routing**: think of SKILL.md as an intelligent router
(like a MoE architecture) — route to sub-commands as inferred, load files only on condition
(auto-load `codex.md` under Codex, `brand.md` for a landing page). Impeccable routes 23 commands
through one SKILL.md; **each loads exactly one expert reference and leaves the other 22 out of
context.**

**#4 — Give them memory** (resumable agents, multi-session refactors, migrations).
Skills needn't be stateless; bundle scripts that persist state across the skill lifecycle.
`/critique` writes a snapshot per target (score, P0/P1, markdown + frontmatter); `/polish` reads
the latest snapshot as its fix backlog. Non-obvious key: **the snapshot slug comes from the
resolved file path, not the phrasing** — a teammate pointing at the same file inherits the same
memory, and the score trend (24→28→32) survives across sessions.

**#5 — Scripts that talk back** (environment-aware setup, dynamic onboarding, repo-state gating).
LLMs compress long skills like a human skimming. Deliver **just-in-time**: at a critical
step/fork, run a script and put the instruction in its **stdout**; "follow whatever the script
prints." `context.mjs` prints `NO_PRODUCT_MD` → the agent stops and runs init. "The exit value is
the prompt." *Trade-off: this breaks prompt caching* — decide cache-hit vs obedience case by case.

**#6 — Hooks that fight back** (lint/format, secret detection, a11y, policy).
Everything above only helps when invoked; the agent's worst edits happen when nobody called the
skill. **Hooks** (Claude Code, Codex, Copilot, Cursor — shippable alongside skills/plugins) run
on every event regardless of invocation. Impeccable's `PostToolUse` hook runs after every file
edit, no-ops on irrelevant files, else scans with a deterministic slop engine and **injects
findings as a system reminder** the agent then fixes — uninvited. *Blind spot:* a static hook
scans disk, not runtime-generated UI. *Warning:* hooks can wreck UX (burn tokens, slow sessions,
overcorrect) — weeks of calibration + a robust false-positive ignore mechanism.

**#7 — Live-wire the browser** (visual iteration, dashboard tuning, painful-to-type UI).
The last 20–30% of polish is miserable to steer by typing. Turn the in-app browser into one of
the agent's **input devices**: `/impeccable live` injects a picker into the dev page, the agent
runs ONE blocking command (`live-poll.mjs`) and waits; you select+generate in the app → that
becomes the returned event; the agent edits in the same thread and the page updates. Devil in
details: **Claude Code can wake from background tasks, Codex cannot** (hence the blocking poll).

**#8 — Compile to every harness** (multi-IDE plugins, cross-runtime, write-once distribution).
A skill built/tested on one model/harness combo underwhelms a teammate on another. **The
differences that bite are behavioral**, not cosmetic — *"some tech bro on X promised me I could
just symlink `.claude` to `.agents`… too good to be true."* Examples: sub-agents spawn
differently (Codex needs explicit permission); Codex only recently could ask questions outside
plan mode; Claude auto-wakes the thread on background-job exit, others don't; harnesses have
different built-in tools; and **every model overfits its own way** (Gemini animates images on
hover; GPT crushes display type to `letter-spacing: -0.06em`), so stacking one model's "don't do
X" into a shared skill regresses the others. Fix: **treat the skill as source code with a build
step.** One source (`SKILL.src.md`): "ask the user" compiles to `AskUserQuestion` on Claude / the
input tool on Codex / plain chat on Cursor; command prefix flips `/`↔`$`; per-model bans compile
only into that model's build. One source → 10+ provider builds. (Note: `npx skills` and similar
installers don't support multi-harness skills; Impeccable ships its own `npx impeccable` CLI;
some skills like agent-browser rewrite themselves on the fly post-install.)

**#9 — Design for the weakest model** (cheap-model deploys, long agentic flows, CI gates).
Weak models amplify skill-prose weaknesses: unclear instructions → they trip (frontier infers &
course-corrects); many steps → they "compress" and skip; lots of context → they compress and
ignore most of it. For max adoption you can't support only GPT+Claude latest — also Sonnet, GPT
5.6 Terra/Luna, Composer, Grok, Kimi, Deepseek, Gemini, GLM. **Build for the dumbest model you'll
actually run on.** Impeccable: explicit un-skippable gates ("You must stop at every gate… shape
confirmation alone is NOT a green light to start coding"; "compressing gates 2–4 is the dominant
failure mode"); `live.md` is step-by-step with nothing implicit (Haiku is the test baseline).
**"If the gate in your skill can be skipped, it will be. Make it un-skippable."**

### Building effective skills

Very little of the advice was about the words. A great skill isn't a prompt with accessories —
"it's a harness extension: it spawns sub-agents your harness wouldn't, guards edits you never
asked it to check, holds memory the session doesn't have, compiles itself into runtimes it's
never seen." Iterate the prose forever — but **what breaks the median is everything around it.**
(Impeccable is open source: `npx impeccable skills install` / impeccable.style; talk deck +
runnable starter at github.com/pbakaus/impeccable-talks.)
