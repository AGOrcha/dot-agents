# Homebrew packaging

Two tracks. The tap is live today; the core formula is a staged draft for later.

## Tap (current, primary)

`da` ships via our own tap, generated by GoReleaser (`.goreleaser.yaml`
`homebrew_casks`). Install:

```bash
brew install agorcha/tap/da
```

The tap **cask** downloads the prebuilt binary from GitHub releases — no Go on the
consumer's machine. At install time Homebrew runs `da completion <shell>` (Cobra)
to generate bash, zsh, fish, and PowerShell completions for the installed
binary. The darwin binaries are Developer ID-signed and notarized as of v0.4.0.

## Core formula (`da.rb`, draft — future)

`da.rb` is a **staging draft** of a build-from-source formula for submission to
[homebrew-core](https://docs.brew.sh/Adding-Software-to-Homebrew). It is **not**
submitted yet.

Why not yet:

- **Notability.** homebrew-core requires a notable, maintained project
  (rule of thumb ~75 stars / 30 forks / 30 watchers, holistically judged). A new
  repo gets the PR auto-closed.
- **Repo identity.** The formula's `homepage`/`url`/module path should point at the
  final repo, so submit after the AGOrcha cutover.

How bottles make Go a non-issue: a core formula declares `depends_on "go" => :build`
(build-time only). On acceptance, Homebrew's CI compiles it and publishes
**bottles** (precompiled per-OS/arch binaries). `brew install da` then downloads a
bottle — the consumer never needs Go. Bottles arrive via brew (not a browser
download), so they also sidestep the Gatekeeper/quarantine problem the tap cask
works around.

### Submission checklist (do later)

1. Cutover complete; pick the first post-cutover tag.
2. In `da.rb`: set `url` to the tagged source tarball; fill `sha256`
   (`shasum -a 256` of the tarball, or `brew fetch`).
3. Confirm no existing core formula installs a `da` binary; add `conflicts_with` if so.
4. `brew audit --new --formula da` and `brew style da` clean.
5. Open the PR per
   <https://docs.brew.sh/How-To-Open-a-Homebrew-Pull-Request#formulae-related-pull-request>.
